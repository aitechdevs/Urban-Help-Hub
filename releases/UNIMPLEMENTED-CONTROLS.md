# Existing features without a connectable frontend implementation

- **Administrator Customers sidebar and View customers statistics card:** the export contains a customer count, but no customer-management page, panel or list API. These existing controls are explicitly disabled with an explanatory title. No fake customer page was added.
- **Editable Customer account settings/profile:** the existing Account settings link opens the existing read-only profile section. Editing name/email/phone/password has no corresponding frontend form or backend endpoint in this export. Country/language preferences remain available through the existing Region selector, now also accessible in mobile menus.
- **Stripe Checkout, Stripe Connect onboarding and the Helper Stripe payout dashboard:** Laravel endpoints and provider logic exist, but the complete exported frontend contains no Checkout button, Connect onboarding button or connected-account dashboard/payout link. This patch does not invent a payment UI or modify provider logic. Existing customer payment summaries, helper earnings and admin payment controls remain intact. Live/test-mode Stripe transactions could not be exercised through this frontend; endpoint authentication and service-worker bypass were verified.
- **Dedicated message pages `/messages` and `/helper/messages`:** the backend emits these links, but no such frontend routes exist. Notification links are mapped to the existing Customer/Helper dashboard message sections. Those sections now use the already implemented GET `/messages` and POST `/tasks/{id}/messages` APIs. They show real, permission-scoped task conversations rather than static placeholders.
- **Separate earnings page:** none exists. The Helper Earnings tab opens the existing completed-work section, which already displays earnings and payout status. No earnings or commission calculation was changed.

There are no additional Settings, Services, Notifications or Payments routes to invent. Existing service/profile editing stays at `/become-a-helper`; notifications use the shared bell; Admin payment navigation opens its existing payment panel. The Helper and Administrator tablet navigation expose the same destinations at the application's existing sm/lg breakpoints.

## Platform limits

Native app-install eligibility depends on the browser and user engagement. Automated tests exercise the captured event and user-click behavior with synthetic events, not an actual operating-system installation. iOS guidance and standalone detection were checked with emulation; a physical iPhone/iPad Safari check is still required. Safari cannot reliably reveal installation status from a normal browser tab; standalone home-screen windows are detected and suggestions are suppressed there.
